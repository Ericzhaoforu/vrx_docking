## Goal

Implement strict GCOPTER-style MINCO-S3NU trajectory generation for the USV flat output

\[
z = [x, y, \psi]^T.
\]

The MINCO module must generate a `FeasibleReference`-compatible local trajectory for the existing flatness-MPC/NMPC tracker. It must not replace the tracker.

## Mathematical requirements

This is not a generic spline optimizer.

Do not optimize polynomial coefficients directly.
Do not implement a coefficient-space QP and call it MINCO.

The outer optimization variables must be:

- intermediate points `q_1, ..., q_{M-1}`;
- time variables `theta` or positive segment times `T_i`.

The polynomial coefficients must be generated by the strict MINCO-S3NU linear system:

\[
A(T)c = b(q,H,G).
\]

The original constrained trajectory optimization problem has:

- objective: minimum-jerk smoothness and optional total-time regularization;
- constraints: lateral generalized-force bound, body-frame velocity bounds, body-frame acceleration bounds, and differential-thrust actuator bounds.

The implementation must convert continuous-time constraints into dense quadrature penalties. The actuator constraints must use:

\[
T_L = \frac{1}{2}\left(\tau_u - \frac{\tau_r}{l}\right),
\qquad
T_R = \frac{1}{2}\left(\tau_u + \frac{\tau_r}{l}\right),
\]

with

\[
T_{\min} \le T_L,T_R \le T_{\max}.
\]

The lateral generalized-force bound must be configurable:

\[
|\tau_v(t)| \le \bar{\tau}_v.
\]

Start with a loose `tau_v_bar` and support tightening it later.

## State-estimation constraint

The estimator only provides `z` and `z_dot`, not `z_ddot`. Do not read acceleration from state estimation.

Strict MINCO-S3NU requires PVA boundary conditions. Implement a boundary acceleration policy:

1. use previous accepted MINCO trajectory acceleration if available;
2. else use previous NMPC predicted acceleration if available;
3. else estimate `z_ddot` from nominal dynamics and last applied command if available;
4. else use zero acceleration for the first run.

Terminal acceleration defaults to zero unless a terminal motion profile provides it.

## Phase-by-phase execution

Proceed phase by phase. Do not jump ahead.

### Phase 0: Repository audit
Confirm existing functions/classes and do not duplicate them unnecessarily:

- flatness mapping utilities;
- `theta_tau_nominal` or equivalent;
- generalized force to differential-thrust mapping;
- `FeasibleReference` or current NMPC reference interface;
- current NMPC controller config and launch files.

Update `docs/minco_implementation_status.md` with findings.

### Phase 1: Strict `MINCO_S3NU` core
Implement a strict `MINCO_S3NU` class. It must support:

- `set_conditions(head_pva, tail_pva)`;
- `set_parameters(inPs, ts)`;
- `coefficients()`;
- `sample(t)` returning `z`, `z_dot`, `z_ddot`, and higher derivatives needed for checks;
- `get_energy()`;
- coefficient/time direct gradients;
- adjoint gradient propagation from coefficient/time gradients to `inPs` and `ts`.

### Phase 2: Unit tests
Add tests for:

- start PVA constraints;
- terminal PVA constraints;
- intermediate point pass-through;
- velocity continuity;
- acceleration continuity;
- jerk continuity;
- snap continuity;
- analytical jerk energy vs numerical quadrature;
- adjoint gradient vs finite difference.

Do not proceed until these tests pass.

### Phase 3: USV dense quadrature constraints
Implement dense quadrature penalties for:

- lateral generalized-force bound `|tau_v| <= tau_v_bar`;
- body-frame velocity bounds;
- body-frame acceleration bounds;
- actuator bounds through `T_L,T_R`.

Do not add input effort, allocation effort, velocity cost, acceleration cost, guide cost, obstacle cost, or corridor cost.

### Phase 4: Outer optimizer
Implement optimization over:

- `vec(inPs)`;
- time variables `theta`.

Use positive time parameterization. If total time is fixed, use softmax segment times:

\[
T_i = T_s \frac{\exp(\theta_i)}{\sum_j \exp(\theta_j)}.
\]

The objective is:

\[
\bar J = E + J_{time} + \lambda_{\tau_v}P_{\tau_v} + \lambda_\nu P_\nu + \lambda_a P_a + \lambda_T P_T.
\]

### Phase 5: FeasibleReference export
Export MINCO trajectories into the existing NMPC reference format. The output must include:

- `z`;
- `z_dot`;
- `z_ddot`;
- body velocity `nu`;
- body acceleration `nu_dot` if needed;
- nominal generalized force `tau`;
- left/right thrust diagnostics;
- constraint diagnostics.

### Phase 6: Offline validation
Create an offline script/test that generates at least:

- a straight local terminal reference;
- a gentle arc local terminal reference.

Report before/after optimization metrics:

- objective;
- `max_abs_tau_v`;
- `rms_tau_v`;
- velocity violation;
- acceleration violation;
- actuator-bound violation;
- terminal error;
- PVA residual;
- continuity residual;
- gradient-check error.

### Phase 7: NMPC integration
Add `reference_source := minco` while preserving current behavior for `reference_source := synthetic`.

Do not replace the existing NMPC controller.
Do not implement PID fallback.

### Phase 8: Gazebo validation
Only after offline tests pass, run Gazebo/VRX closed-loop validation with the existing NMPC tracker and MINCO reference. Report solver success, tracking error, actuator saturation, and constraint diagnostics.

## Stop conditions

If a phase fails, perform at most three focused repair attempts. Each attempt must include:

1. hypothesis;
2. minimal code/config change;
3. rerun of relevant tests;
4. metric comparison.

After three failed attempts, stop and write a rigorous failure analysis. Do not continue to later phases.

## Explicit non-goals

Do not implement:

- front-end planning;
- obstacle corridors;
- ESDF/costmap obstacle constraints;
- NN residual compensation;
- new thrust-space MPC;
- PID fallback;
- generic polynomial coefficient optimizer masquerading as MINCO.

## Success criteria

Do not claim success unless these are reported:

- commands run;
- tests passed/failed;
- PVA boundary residual;
- continuity residual;
- gradient-check error;
- `max_abs_tau_v` and `rms_tau_v`;
- velocity/acceleration/actuator violations;
- offline objective before/after;
- integration status with the existing NMPC reference interface.
